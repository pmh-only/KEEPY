# KEEPY 🌱

각자 쓴 편지를 함께 봉인하고, 나중에 열쇠를 모아 여는 타임캡슐 MVP.

## 실행

Node.js 22.12 이상 권장.

```sh
npm install
npm run dev
```

http://localhost:5173 에서 방을 만들고, 초대 링크를 다른 브라우저나 탭에서 열면 됩니다. 두 탭에서 각각 작성 완료 → 방장이 봉인 → 각자 HTML 다운로드.

실제 다른 기기에서 사용할 때는 **HTTPS**가 필요합니다. localhost 이외의 일반 HTTP 주소에서는 브라우저 암호화 API를 사용할 수 없습니다.

```sh
npm run build
npm start
```

프로덕션 서버: http://localhost:3001 (`PORT`로 변경 가능). HTTPS 리버스 프록시 뒤에 두고 `/ws` WebSocket 업그레이드도 전달하세요. 서버는 한 프로세스로 실행합니다. DB나 공용 방 저장소가 없으므로 여러 인스턴스로 수평 확장하는 구성은 지원하지 않습니다.

## 컨테이너 실행

```sh
docker compose up --build -d
```

http://localhost:3001 에서 접속합니다. 포트를 변경하려면 `KEEPY_PORT=8080 docker compose up --build -d`로 실행하세요.

```sh
docker compose logs -f
docker compose down
```

화면과 연결 서버를 하나의 이미지로 묶습니다. 실행 이미지에는 빌드 결과만 포함하며, 관리자 권한 없이 읽기 전용으로 실행합니다. 별도의 DB나 저장 공간은 필요하지 않습니다. 컨테이너를 재시작하면 진행 중인 방은 사라집니다.

외부 기기에서 사용하려면 HTTPS를 제공하는 프록시나 터널 뒤에 두세요. `/ws` 연결도 함께 전달해야 합니다. 이 구성은 HTTP만 제공하며 인증서를 자동 발급하지 않습니다.

## GHCR 자동 배포

`.github/workflows/ghcr.yaml`에서 `main` 푸시, `v*` 태그 푸시 또는 수동 실행 시 이미지를 게시합니다.

- amd64: `ubuntu-24.04`에서 `linux/amd64`만 빌드
- arm64: `ubuntu-24.04-arm`에서 `linux/arm64`만 빌드
- 두 이미지가 모두 올라오면 digest를 모아 멀티 아키텍처 이미지를 생성
- QEMU를 사용하지 않으며, 두 빌드가 성공해야 최종 태그를 게시
- 별도 비밀번호 없이 GitHub에서 제공하는 `GITHUB_TOKEN` 사용

이미지: `ghcr.io/pmh-only/keepy`

- `main` → `:latest`, `:sha-커밋`
- `v1.2.3` → `:v1.2.3`, `:1.2.3`, `:1.2`, `:sha-커밋`

```sh
docker pull ghcr.io/pmh-only/keepy:latest
```

기기에 맞는 이미지를 자동으로 선택합니다. 처음 게시한 패키지가 비공개라면 GHCR 패키지 설정에서 공개로 바꾸거나 로그인 후 내려받으세요. 이미 같은 이름의 패키지가 있다면 이 저장소에 패키지 쓰기 권한이 있어야 합니다.

## 포함한 기능

- 방 생성·초대, 최대 12명 참여, 각자의 텍스트 메시지(4,000자)
- 친구·커플·미래 템플릿, 최소 개봉 인원, 공개 범위, 작성자 추가 열쇠, 예정일
- WebRTC 직접 연결, 실패하거나 연결 대기 중이면 **종단 간 암호화된 WebSocket 릴레이**
- 참여자별 연결·작성·다운로드 시작 현황, 전원 다운로드 시작 시 완료 페이지 표시
- 각자 브라우저에서 암호화하고 개인별 독립 HTML 생성
- 인터넷 없이 HTML을 직접 열어 QR 또는 단어열 키를 모아 복호화
- 오프라인 캡슐도 동일한 모바일 UI로 열쇠 공유 → 열쇠 모으기 → 편지 읽기 진행
- QR 표시·PNG 저장·카메라 스캔·QR 이미지 불러오기 (모든 처리는 브라우저 안에서 수행)

## 구현 구조

```text
src/App.tsx            화면
src/session.ts        봉인·개봉 파일 생성 프로토콜
src/transport.ts      WebRTC / 암호화 WebSocket 릴레이
src/shared/           암호화·SSS·단어열·파일 형식
offline/main.ts       오프라인 복호화 전용 앱
scripts/              오프라인 앱을 단일 스크립트로 번들
server/index.ts       정적 파일·메모리 방·시그널링·즉시 릴레이
```

React + Vite + TypeScript / Node.js + ws. 화면은 CSS와 lucide-react를 사용합니다. DB, 회원가입, 메시지 복구 기능은 없습니다.

## 암호화와 보관

- 루트 키는 브라우저에서 무작위 32바이트 생성. `shamir-secret-sharing`으로 k-of-n 분할. k=1은 각자 같은 루트 비밀을 보관하는 별도 형식입니다.
- 메시지는 루트 키와 독립적인 작성자 비밀키(옵션)를 HKDF-SHA-256에 넣어 유도한 AES-256-GCM 키로 암호화합니다. IV는 메시지마다 무작위 12바이트입니다. 캡슐 ID·설정·인원·작성자 정보를 인증 데이터에 결합합니다.
- 전달 키는 참여자별 ECDH P-256 결과와 **초대 URL fragment의 비밀값**으로 유도합니다. 초대 비밀은 서버에 보내지 않습니다. 방 코드 전체/링크를 가진 사람만 입장에 필요한 비밀을 가집니다. 시그널링 정보도 암호화합니다.
- 릴레이 서버는 암호문을 즉시 전달할 뿐 DB·파일·로그에 저장하지 않습니다. 방 메타데이터(이름·ID·공개키)는 실행 중인 서버 메모리에만 있습니다.
- 현재 릴레이는 coturn이 아니라 자체 WebSocket 방식입니다. URL에 `?relay=1`을 붙여 만들거나 입장하면 WebRTC 없이 릴레이를 테스트할 수 있습니다. WebRTC STUN은 Google의 공개 STUN을 사용합니다.
- 단어열은 BIP39 영어 단어 목록을 사용하는 **KEEPY 전용 인코딩**입니다. 지갑용 BIP39 니모닉이 아닙니다. 버전·키 종류·캡슐 ID·참여자 ID·키 데이터·4바이트 체크섬을 포함합니다.
- 오프라인 파일에는 본인의 SSS 조각과 작성자 비밀키가 들어 있습니다. 개인 파일을 공개하지 마세요. 전체 공개 모드에서는 모든 암호문, 본인만 보기에서는 본인 암호문만 들어갑니다.
- 개봉 시 다른 사람의 HTML 자체를 받는 대신, 파일에 표시된 QR을 스캔하거나 QR 이미지를 전달합니다. QR 하나에 본인의 개봉 열쇠와 작성자 추가 열쇠(사용하는 경우)를 함께 담습니다. 카메라를 지원하지 않거나 권한을 허용하지 않은 브라우저에서도 QR 이미지를 불러올 수 있습니다. 복사·붙여넣기도 유지하며 단어열은 한 줄에 한 열쇠, 작성자 보호 모드는 두 줄입니다.
- 개봉일은 UI 제한이며 시계 변경·파일 수정으로 우회할 수 있습니다. 루트 키는 사용 후 참조를 제거하고 바이트 배열을 덮어쓰지만 JS 런타임의 완전한 메모리 소거를 보장하지는 않습니다.

## MVP 제약

방장이 나가면 방이 닫히고, 새로고침 시 진행 중 상태가 복구되지 않습니다. 봉인 중 연결이 끊기거나 60초 안에 완료되지 않으면 새 방에서 다시 시작해야 합니다. 방장이 초대를 마감하면 서버가 신규 입장을 차단하고 설정 화면으로 이동합니다. 이전 화면으로 돌아가도 초대는 다시 열리지 않습니다. 다운로드된 파일은 서버와 무관하게 계속 사용할 수 있습니다.

직접 연결 표시는 연결 상태이며, 큰 프레임은 브라우저 전송 한도를 피하기 위해 암호화 릴레이로 전달할 수 있습니다. 실제 디스크 저장 완료는 브라우저에서 알 수 없으므로 다운로드 시작을 기준으로 현황과 완료 페이지를 표시합니다.
